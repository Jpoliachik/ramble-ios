# Ramble Backend API Skill

This skill describes how to implement a backend that works with the Ramble iOS voice journaling app. The app uploads raw audio recordings to the backend, which handles transcription and optional LLM processing.

## Setup: API Key Generation

On first deploy (or when no key exists yet), the backend MUST:

1. **Generate a secure random API key** — e.g. 64-character hex string or UUID v4. This is a shared secret between the backend and the iOS app.
2. **Store it privately** — Save the key wherever the backend keeps private config (environment variable, `.env` file, secrets manager, encrypted config file — whatever fits the stack). It must NOT be committed to source control.
3. **Display it to the user exactly once** — Print the key to stdout on first run, or write it to a setup output file, so the user can copy it. Make it obvious: `"Your Ramble API key: <key> — paste this into the iOS app Settings."`

The user then opens the Ramble iOS app → Settings → pastes two things:
- **Base URL** — the host where the backend is running (e.g. `https://my-server.com`)
- **Auth Token** — the API key generated above

That's it. Those two values are all the app needs to connect.

## API Contract

### Authentication

All endpoints require:
```
Authorization: Bearer <token>
```

The `<token>` is the API key generated during setup. Compare it against the stored key. Return `401 Unauthorized` if the token is missing or doesn't match.

### POST /ramble/recordings

Upload a new audio recording for processing.

**Content-Type:** `multipart/form-data`

**Parts:**
- `audio` — The audio file (.m4a, 16kHz mono AAC). Has `Content-Type: audio/m4a` and a `filename`.
- `metadata` — A plain text form field containing a JSON string (no `Content-Type` header — defaults to `text/plain` per RFC 7578). Parse it with `JSON.parse()` or equivalent on the server side.
  ```json
  {
    "id": "uuid-string",
    "created_at": "2026-02-22T10:30:00Z",
    "duration": 125.3
  }
  ```

**Responses:**
- `202 Accepted` — Recording received, processing started. If a recording with this ID already exists, the job is reset and reprocessed (idempotent).
  ```json
  {
    "id": "uuid-string",
    "status": "processing"
  }
  ```
- `401 Unauthorized` — Bad or missing token

### GET /ramble/recordings/{id}

Poll for processing results.

**Responses:**
- `200 OK`
  ```json
  {
    "id": "uuid-string",
    "status": "processing" | "completed" | "failed",
    "transcription": "The full transcription text...",
    "agent_notes": "## Summary\n...",
    "error": "Error message if failed"
  }
  ```
  - `transcription`, `agent_notes`, `error` are only present when relevant
  - `status` progresses: `processing` → `completed` or `failed`
- `401 Unauthorized`
- `404 Not Found`

### DELETE /ramble/recordings/{id}

Delete a recording and its associated audio/data.

**Responses:**
- `200 OK` or `204 No Content` — Recording deleted
- `401 Unauthorized`
- `404 Not Found` — Recording doesn't exist (treat as success — already deleted)

The app sends a fire-and-forget DELETE when a user deletes a recording locally. The backend should delete the audio file, metadata, transcription, and agent notes associated with the recording.

### GET /ramble/recordings (future)

List all recordings. Not currently used by the app but reserved for future sync.

## Audio Format

- Container: M4A (MPEG-4 Audio)
- Codec: AAC
- Sample rate: 16,000 Hz
- Channels: 1 (mono)
- Typical file sizes: ~100KB per minute of speech

## Implementation Guide

### Minimum Viable Backend

1. **Receive upload** — Parse multipart form, store the audio file and metadata
2. **Transcribe** — Use any speech-to-text service (Whisper, Groq, Deepgram, AssemblyAI, etc.)
3. **Return results** — Set status to `completed` with the transcription text

### Enhanced Backend (with LLM processing)

After transcription, run an LLM to produce `agent_notes`. Example prompt:

```
Given this voice journal transcription, produce markdown notes with:
- A brief summary (2-3 sentences)
- Action items (if any)
- Key topics/tags

Transcription:
{transcription_text}
```

### Example `agent_notes` Output

```markdown
## Summary
Discussed weekend plans including a hiking trip to Mount Tam and grocery shopping.
Mentioned needing to follow up with the dentist about rescheduling.

## Action Items
- [ ] Book hiking trail permit
- [ ] Call dentist to reschedule
- [ ] Buy groceries for the week

## Tags
#personal #outdoors #errands #health
```

### Storage

- Store audio files durably (local filesystem, S3, GCS, etc.)
- Store metadata + results in any database or JSON files
- The `id` field is a UUID generated by the client — use it as the primary key

### Processing Flow

```
POST /ramble/recordings
  → Store audio + metadata
  → Begin async processing
  → Return 202

Background:
  → Transcribe audio
  → (Optional) Run LLM on transcription
  → Update status to completed/failed

GET /ramble/recordings/{id}
  → Return current status + results

DELETE /ramble/recordings/{id}
  → Delete audio file + metadata + results
  → Return 200/204
```

### Error Handling

- If transcription fails, set `status: "failed"` and `error: "description"`
- The app will retry uploads with exponential backoff (5s to 180s, max 5 retries)
- The app polls for results with backoff (3s to 30s, max 20 polls)
